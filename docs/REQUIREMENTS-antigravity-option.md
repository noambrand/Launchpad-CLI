# Requirements: Google Antigravity CLI as a fourth agent (v3.5.0)

*Follows `REQUIREMENTS-codex-option.md` and `REQUIREMENTS-copilot-option.md`: every rule there about Claude staying frozen, user text never passing through a shell, no PowerShell in Launchpad's own code, no new dependencies, and no bypass flags applies here too. Real Antigravity behavior: `STEP0-results-antigravity.md`. Manual release tests: `MANUAL-TESTS-v3.5.0.md`.*

## Noam's decisions (2026-11-08)

| # | Decision |
|---|---|
| G1 | **Antigravity CLI (`agy`), not Gemini CLI.** Since 2026-06-18 Gemini CLI no longer serves free or Google AI Pro/Ultra accounts; that access moved to Antigravity CLI. |
| G2 | "Opt out in the installer if possible, if not then tell users to do that before using." Google's use of what users type is a tick, already set, on Antigravity's first-run "Terms of Service & Data Use" screen, kept with the account. The installer can't preset it, so Launchpad tells users to clear it (D12). |
| G5 | **`done` sound only.** Antigravity has no event for an approval prompt. |
| G6 | **A Launchpad status line for Launchpad's Antigravity launches:** model, context used, weekly quota left, and when it resets. |
| G7 | **Refuse `--remote-control` and `--remote-agent`** in a profile's flags, with the approval bypasses. |
| C4 | Wording follows Codex's and Copilot's: "Open with Antigravity CLI", "Open Antigravity CLI here", "Launch Antigravity CLI"; the installer choice is "Antigravity (Google)". The agent id in `config.txt` and profiles is `antigravity`. |

## Design decisions, and the facts behind them

| # | Decision | Why |
|---|---|---|
| D1 | `configure-antigravity.js` requires `configure-codex.js` and `agent-helpers.js` and reuses their exports, as `configure-copilot.js` does. Neither of those two files may require a new file. | Two locked tests copy exactly `configure-codex.js` and `agent-helpers.js` into a sealed folder (Copilot's D1). |
| D2 | Start `agy.exe` directly with an argument array (`spawnSync`, no shell). | `%PATH% ^ & \| < > ! "q"` and Hebrew arrive unchanged (A8). |
| D3 | Install with Google's own `install.cmd`, downloaded by Launchpad and started as `cmd.exe /d /c <file>` with no `&&`. Then Launchpad finds `agy.exe` itself and runs `agy --version`; the minimum is **1.5.3**. Exit code **7** on failure. | The script checks the download against Google's SHA-512 and needs no PowerShell or administrator. It refuses to run when its own command line holds `& \| ; < > ^`, and it exits 0 even when its last step fails, so its exit code proves nothing. 1.5.3 is the only version tested. Launchpad doesn't check the Authenticode signature: that needs PowerShell or `signtool`, and users have neither. Google's script runs under `install.cmd`'s curl settings (`ssl-no-revoke`), as Anthropic's bootstrap already does, so certificate revocation isn't checked for that download; Node's own download of the script doesn't check revocation either. |
| D4 | Finding the copy: `%LOCALAPPDATA%\agy\bin\agy.exe` first, then `agy.exe` on PATH. The verified path is cached in `kivun-antigravity-path.txt`, as for the other agents. When Antigravity is selected and a copy exists, run `agy update` (60-second limit); a failure keeps the copy. | Google's script installs there; winget's package may put it elsewhere. Antigravity also updates itself every 15 minutes, so the update is only a head start (Copilot's D20). |
| D5 | Continue is plain `-c`. A new conversation is no flag. "Choose from a list" starts a normal session and first prints one line: "Type /resume to choose a conversation." | `-c` opens this folder's conversation, or a new one, never another folder's (A4). `-i "/resume"` is sent to the model as text, so the list can't be opened from outside (A5). |
| D6 | Start agy in the folder's real spelling, `fs.realpathSync.native(folder)`. | Antigravity matches folders case-sensitively: `C:\KT\AGY\W1` and `C:\kt\agy\w1` are two folders to it (A4). |
| D7 | First message: `-i <text>`, any text, including text starting with `-` or `/`. | `-i` waits behind the trust screen and is sent once; a leading `-` is kept (A5). Text starting with `/` goes to the model as a message, which is still the user's text. |
| D8 | One plugin folder of Launchpad's own: `~\.gemini\config\plugins\launchpad\` holding `plugin.json`, `hooks.json`, `hook.cmd` and `antigravity-hook.js`. It honors `USERPROFILE`. Uninstall deletes the folder. No change record. | A plugin there loads with no trust screen (A7), and Launchpad never edits the user's `hooks.json`, which the Antigravity app and IDE share. |
| D9 | **Every hook command is relative and has no quotes:** `.\hook.cmd session-start` and `.\hook.cmd stop`. `hook.cmd` is exactly `@node "%~dp0antigravity-hook.js" %*` (CRLF), so it holds no path of its own. | Antigravity runs hook commands through `cmd /c` with their quotes broken: `node "C:\a b\x.js"` reached Node as `"C:\a`. Hooks run in the plugin folder. The `.\` is needed where `NoDefaultCurrentDirectoryInExePath` is set. `%~dp0` keeps a Hebrew or spaced user folder out of the command (simulated, A7), and a `.cmd` file is read in the console's code page, so it must hold no non-ASCII text. A bare `node`, as Copilot's hook file uses. |
| D10 | Language: `SessionStart` adds `{"injectSteps":[{"systemMessage":{"systemMessage":"<line>"}}]}` only when the session's environment has `KIVUN_ANTIGRAVITY_LANGUAGE_LINE`; Launchpad sets it to `copilotLanguageLine(code)`'s text. Otherwise the hook prints `{}`. | Hebrew 4 of 4 (A6). Sessions started by hand, and the Antigravity app and IDE, get nothing. The line stays in the conversation, so Continue keeps it. Copilot's firmer wording, because Claude's and Codex's are frozen. |
| D11 | `done`: `Stop` with `terminationReason` `NO_TOOL_CALL`, and only when the environment has `KIVUN_ANTIGRAVITY=1`. The hook starts `~\.claude\sounds\play.js done` with no pipes and returns at once, printing `{}`. Any other reason (an interrupt, an error, a limit) plays nothing. | Once per turn, including turns with tool calls; not while an approval prompt shows; not after Esc (A7). Hooks block the turn (Copilot's D12). The variable keeps sounds out of the Antigravity app and IDE, which load the same plugin. `play.js` already obeys Sound OFF. |
| D12 | Data use (G2): the picker's note for Antigravity and Quick Start say, before the first task: "On Antigravity's \"Terms of Service & Data Use\" screen (shown once, after the sign-in and the colour scheme), press Enter to clear the tick (Google uses what you type while it is ticked), then press the Down arrow, then the Right arrow to reach Done, and press Enter. You can also turn it off later: type /config, then Enable Telemetry." The installer's Antigravity note and finish page carry the first part (clear the tick, then Down, Right, Enter on Done), because the finish page shows about five lines and a larger one would change Claude's frozen finish page. Keys in words, not arrow symbols: the installer script must stay ASCII. | A3. In Step 0, Down moved the selection from the tick to "Previous", and Right moved it to "Done" (screens `a2-05`, and the two key presses after it). The screen's own hint ("↑/↓ Navigate · enter Toggle") doesn't mention Right, so the manual test sheet's data-use row confirms it on a fresh sign-in before release. |
| D13 | Status line (G6): Launchpad passes `--settings` with `{"statusLine":{"type":"command","command":"antigravity-statusline.cmd","enabled":true,"stack_with_default":true}}` **unless the user's own `~\.gemini\antigravity-cli\settings.json` has a `statusLine` key.** It puts the Kivun folder first on PATH for the agy process only, so the bare name is found. `antigravity-statusline.js` reads the JSON on stdin and prints one line: model, context used (`context_window.used_percentage`), weekly quota left (`quota["gemini-weekly"].remaining_fraction`) and its reset day and hour (`reset_time`), each part left out when missing. | `--settings` is per session and never saved (A10). The command runs in the user's folder and can't hold quotes, so it must be found by name; tested from a Hebrew folder with a space. A user who chose a status line keeps it. |
| D14 | Refuse in profile flags: `--dangerously-skip-permissions`, `--mode auto` and `--mode=auto`, `--settings` and `--settings=…`, `--remote-control`, `--remote-agent`. Narrow choices (`--mode plan`, `--mode accept-edits`, `--model`, `--effort`, `--sandbox`) stay the user's. | The same rule as D14 for Copilot. A user's `--settings` could set `toolPermission: always-proceed` or `agentMode: auto`, and Launchpad uses `--settings` itself (D13). G7. |
| D15 | For the agy process: `KIVUN_ANTIGRAVITY=1`, the language line (D10), the PATH change (D13), and `PSExecutionPolicyPreference=RemoteSigned` when no script policy was chosen and the variable isn't set — Copilot's rule C3, reused, not copied. | The agent's shell is PowerShell 5.1; `npm -v` fails without it and works with it (A9). |
| D16 | No model list; the model field is free text passed as `--model`. | `agy models` needs a signed-in session. A wrong name is Antigravity's to report. |
| D17 | macOS stays Claude only. | As for Codex and Copilot. |
